# Impeccable — SofiSwap design context

Persistent guidance for AI-assisted design and UI work in this repository. **Update the Design Context section** when brand or product direction changes.

## Design Context

### Users

- **Who**: People trading and providing liquidity on **SofiSwap**, a decentralized exchange on **MySocial**, including users of **Social Proof Tokens** (profile-linked tokens, reservations, pools).
- **Context**: Mix of **marketing / “coming soon”** touchpoints (email signup, countdown) and **dense trading surfaces** (order book, charts, wallet, network switching, GraphQL-driven portfolio data).
- **Job to be done**: Swap and trade with clarity; assess markets and **social proof** status without drowning in noise; sign in and manage wallet/network with confidence.

### Brand personality

- **Voice**: Direct, product-led, slightly technical—**serious about money**, not gimmicky.
- **Three-word personality**: **Calm · Capable · Botanical-tech** — the mint-on-charcoal palette reads organic-meets-terminal without feeling playful or childish.
- **Emotional goals**: **Trust** (clear states, legible type, predictable chrome), **focus** (trade shell separates “terminal” from marketing fluff), **subtle energy** (motion on landing; restrained in trade).

### Aesthetic direction

- **Visual tone**: **Dark-first** app shell (`ThemeProvider` default `dark`; system option enabled). **Mint / sage** as hero accent (`#9AE19D`, `#537A5A`) on **muted charcoal** (`#2C302E`, `#303330`). Secondary/earth accents (`#A68A64` in dark). **Satoshi** is the primary brand typeface across UI; **JetBrains Mono** for code/addresses.
- **Component language**: **shadcn/ui + Radix** primitives, **Tailwind** utility layout, **Lucide** icons. Trade UI uses dedicated tokens (e.g. `--trade-shell-border`, `.border-trade-shell`) so **ticker + header + panels** feel like one instrument panel.
- **References implied by the stack**: Modern DeFi dashboards, polished command-palette search (⌘K), subtle glass/backdrop headers (`backdrop-blur`, semi-transparent backgrounds).
- **Anti-references**: Neon cyberpunk overload, generic “AI slop” purple gradients, clown-vivid palette shifts that fight the existing green system, breaking **trade-shell** border consistency for one-off panels.

### Design principles

1. **Token-first color** — Prefer semantic CSS variables (`background`, `foreground`, `primary`, `muted-foreground`, trade-specific tokens) over raw hex in components so light/dark and future themes stay coherent.
2. **One trade chrome** — Keep `/trade` visuals aligned: `border-trade-shell`, shared density (e.g. ~13px labels where already established), avoid orphan borders or mismatched radii vs sliding tabs / pills.
3. **Readable under load** — Data-heavy tables and charts need hierarchy (weight, muted secondary text, truncation + tooltips where patterns already exist). Destructive and warning states should use existing `destructive` / amber patterns.
4. **Motion with purpose** — GSAP/Framer on landing and emphasis is fine; avoid gratuitous motion in **order entry, balances, or error paths**; respect `prefers-reduced-motion` when adding new animations.
5. **Accessibility as baseline** — Visible focus rings (`ring-ring`, offset), meaningful `aria-label`s on icon-only controls (see trade search trigger pattern), don’t rely on color alone for state.

## Shared trade styling (`/extract`)

Semantic class bundles for repeated trade/SPT UI live in **[`lib/trade-shell-styles.ts`](lib/trade-shell-styles.ts)**:

- `tradeRailSegmentListClass` — segmented control track (nav + workspace rails)
- `tradeSptSwapSegmentShellClass` — inset segment track inside SPT panels
- `tradeSptRoundedPanelClass`, `tradeSptTallCardClass`, `tradeSptEmptyAsideClass` — card surfaces
- `tradeWorkspaceRouteEmptyRootClass`, `tradeWorkspaceRouteLoadingClass` — full-route placeholder / loading frames

Prefer importing these when adding new trade panels instead of duplicating long Tailwind strings.
